# Security Policy

## Scope

Security reports are welcome for the reference implementation, MCP server, examples, and repository automation.

The written standard itself is not software, but security-relevant ambiguities in the tool contract or implementation may also be reported.

## Reporting a vulnerability

Please do **not** disclose a potentially exploitable vulnerability in a public issue before maintainers have had a reasonable opportunity to assess it.

Use GitHub's private vulnerability reporting feature for this repository when available. If that feature is not enabled, contact the maintainer through the repository contact channel and clearly mark the message as a security report.

Please include:
- affected component and version;
- reproduction steps;
- expected vs. actual behavior;
- potential impact;
- suggested mitigation, if known.

## Response goals

This is an independent, early-stage project. We aim to acknowledge credible reports promptly, assess severity, and publish a fix or mitigation transparently when appropriate.

## Supported versions

The current public release is the supported line. Older snapshots may not receive fixes.

## Independence

This is an independent initiative and not an official project of the Holy See or any AI laboratory.
